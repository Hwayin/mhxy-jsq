# 角色测试 JSON

每个角色一个文件：`roles/<应用内部角色ID>.json`。同一角色再次导出会直接覆盖同名文件；不同角色分别保存。

当前测试数据：`roles/muz8mwy5-hilnb0a9.json`，来自 Chrome 中录入的龙宫角色，首次导出包含所属账号、角色信息与 10 笔成本明细，总投入 ¥2,135.00。

2026-10-08，用户选择清除旧装备测试记录、逐件重新录入。当前同 ID 角色文件已同步清理旧样本的 8 条装备类记录，保留召唤兽和坐骑 2 条明细，合计 ¥745.00。清理前的浏览器完整账本及原工程角色 JSON 分别保存在 history 目录；旧格式兼容样本仍保留在 tests/fixtures。

## 更新测试数据

在项目目录运行：

```powershell
npm run test-data
```

保持服务运行，在本机 Web 角色页点击「导出测试 JSON」。文件保存到本目录的 `roles` 子目录，页面显示「已导出」或「已覆盖」。服务仅监听本机 `127.0.0.1:5179`；浏览器本身不能直接覆盖工程文件，因此由这个本地服务完成保存。

## 恢复

Web 端：备份页 →「从 JSON 文件导入」→ 选择对应角色文件 → 确认。

App 端：复制文件内的完整 JSON → 在备份页粘贴 →「检查并导入」→ 确认。

角色备份按应用内部角色 ID 恢复；同 ID 的角色和所属明细整体替换，其他角色保留。所属账号不存在时一起创建；账号已存在时保留其当前别名与队伍信息。原有全账本备份仍按整体替换方式恢复。

App 角色页提供「复制角色 JSON」，用于保存角色备份到自己的文件中。工程内的 JSON 覆盖导出功能用于本机 Web 调试。

v0.2 导出 v2 格式，保留细分类型、组合内容 / 数量和补充属性，同时兼容导入 v1。当前角色文件可随使用更新；旧格式兼容测试使用单独的 `tests/fixtures/legacy-v1.json`，不会用旧数据覆盖本目录下的最新文件。
